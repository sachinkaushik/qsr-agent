# Suspicious Activity (Kitchen Food Safety)

Use the suspicious-activity MCP service as the only source of suspicious-activity
and kitchen food-safety facts. Never answer from memory or an earlier turn when a
fresh tool call is available. Each event is one detected violation with a `zone`,
`pose`, `severity`, `camera_id`, `object_id`, `description`, and `ts_ms`.

## Contract Discovery

Use the connected `suspicious-activity` MCP service's standard tool list to
discover its tools and schemas. Do not require a `describe` call before every
request; `describe` is optional service metadata, not live event evidence. If
the service is unavailable or a needed tool is not listed, say so rather than
guessing.

This service is read-only for runtime operations. It exposes no `act` tools.
Critical alerts are delivered separately through the configured callback and
shown in the QSR Automatic Alerts panel; do not try to create alerts by calling
an action tool.

## Capability Routing

| User intent or question | Required capability | Fields to use | Answer rule |
|---|---|---|---|
| Which zones have activity | `Get_all_zones` | returned zone list | List zones exactly as returned. |
| All or recent events | `Get_all_activities` or `Get_activity_by_zone` | `event_name`, `zone`, `severity`, `description`, `timestamp`, `ts_ms` | Summarize counts and notable events; preserve event fields. |
| Events in a zone and time range | `Get_activity_by_zone_timestamp` | `zone`, `start_time`, `end_time` | Pass ISO-8601 values. Naive times use the store timezone configured by `SAD_TIMEZONE`. |
| Dropped-and-returned food or objects picked up from the floor | `Search_retrospective_frames` or `Get_event_count` | `event_name="food_safety_violation"`, `use_case="kitchen"`, usually `zone="kitchen-prep"` | Prefer structured filters; omit free text or use one distinctive keyword. |
| How many high-severity events | `Get_event_count` | `minimum_severity="high"` | High is a minimum threshold and includes critical events. State the scope and time range used. |
| How often / which station or shift | `Get_trend_counts` | `station`, `shift`, `count` | Report only returned station/shift buckets. |
| Frame evidence | `Search_retrospective_frames` | returned `frame` reference | Report the reference if present. Do not claim an image was fetched; this tool returns logged references. |

## Complex Questions

Prefer structured filters (`zone`, `event_name`, `use_case`, `start_time`, and
`end_time`) over free-text `query`. SAD text matching is literal and requires
all meaningful query words to match; a full natural-language request can filter
out valid events. Use one distinctive keyword or omit `query`.

For counts and trends, use the aggregate tools rather than asking the model to
count a long list. For event details, report `timestamp` (formatted in store
local time) and retain `ts_ms` only when exact machine-readable time is useful.
Do not claim a historical trend from a single snapshot.

## Alerts and Actions

Automatic critical alerts are pushed to the QSR UI through the configured MCP
subscription callback. They are not generated by a tool call during chat.
There are no runtime action tools for notifying operators or opening cases in
this service. If asked to perform an unsupported action, explain that limitation
and point to the Automatic Alerts panel when relevant.

## Owner Extension
